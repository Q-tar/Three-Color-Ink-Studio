# 墨迹 Ink Studio · 墨水屏图片工作台

适用于现有新 PCB（Board2）、ESP32-C3 Super Mini 和 E2213JS0C1/C2 黑白红屏。
本工具在独立的 `image_tool` 文件夹中，未改动上一级已能显示图片的 IDF 工程。

## 直接使用

已生成 Windows 使用包时，双击本目录的 **启动上位机.cmd**，或打开 `dist/InkStudio-WiFi/InkStudio-WiFi.exe`。从 GitHub 下载的源码不含 EXE，请先按本文“开发与重新编译”安装依赖，再运行 `app.py`。
打包版可以直接运行，无需先安装 Python。请保留 EXE 旁的 `_internal`、`firmware` 和说明文件，不能只复制单个 EXE。

1. **导入图片**：支持 JPG、PNG、BMP、WebP，也可以把图片拖进窗口。
2. **调整构图**：选择横屏或竖屏，完整显示或铺满裁切；可以旋转、缩放、拖动原图。
3. **调整颜色**：右侧实时预览黑白红效果。黑色阈值越大，更多区域会变黑；红色识别差值越大，判定为红色越严格。照片可以尝试黑白抖动，文字、图标通常无需开启。
4. **连接设备**：完成下述首次固件安装后，选择 C3 的 COM 端口并点击连接。
5. **发送到墨水屏**：设备先校验整张图片，再执行全屏刷新；窗口会显示写入、升压、刷新、关闭升压等阶段。

## 首次连接真实屏幕

之前的单图显示程序不支持接收上位机图片，需要安装一次配套接收固件。

1. 用有数据功能的 USB 线连接 **ESP32-C3 Super Mini 自身的 USB 口**。仅给 PCB 旁边的电源接口供电不能建立上位机数据连接；屏幕继续使用当前已验证的供电方式。
2. 关闭 VS Code/IDF/Arduino 等正在占用该端口的串口监视器。
3. 点击“扫描”，选择板子的端口，之前通常是 COM9。
4. 点击 **首次安装接收固件**，确认后等待烧录成功。此操作替换板内程序，不改动桌面的原工程。
5. 如端口号发生变化，重新扫描并选择，然后点击 **连接设备**。
6. 出现“握手成功”后再发送图片。安装后不会主动刷新屏幕，收到图片指令才会刷新。

已装好接收固件的板子，直接运行打包版即可，不需要 Python 或 IDF。
首次安装需要 Python 和 esptool，不需 Arduino。脚本优先识别 ESP-IDF 环境，并兼容原电脑路径；
其他电脑也可安装 Python 后执行 `python -m pip install esptool==5.2.0`，然后调用烧录脚本。
多套 Python 并存时，通过 `-PythonPath` 指定安装了 esptool 的 `python.exe`；
也支持 `-EspToolPath` 指定 `esptool.py`。`-CheckOnly` 只校验固件和工具路径，不打开串口。

## Wi-Fi 无线传图（接收固件 1.2）

不需要路由器：C3 自建 2.4 GHz 热点，电脑连接它后使用 HTTP 传图。USB 传图继续可用，首次安装或升级固件仍使用 USB；这不是 OTA 无线烧录。

1. 先用 USB 数据线连接 C3，在上位机 **USB** 模式选择实际 COM 口，点击“首次安装接收固件”，烧入本次提供的 1.2 固件。旧 1.1 固件没有 Wi-Fi 功能。
2. 保持 C3 和屏幕 PCB 供电，电脑 Wi-Fi 连接 **InkStudio-C3**，密码 **inkstudio123**。Windows 提示“无 Internet”时选择保持连接；这个热点不提供互联网。
3. 打开新版上位机，在顶部选择 **Wi-Fi**，地址填写 **192.168.4.1**，点击“连接设备”，等待握手成功。
4. 导入和调整图片，点击“发送到墨水屏”。保存、重绘、CRC 检查及刷新阶段提示与 USB 相同。
5. 网络断开后，设备可能仍在刷新，请继续供电。上传响应丢失时，程序不会自动重传；重新连接并确认屏幕及设备忙状态后再决定是否发送。

Wi-Fi 只替代数据传输，不能给屏幕供电。热点默认最多连接两台设备，同一时间全设备仅接受一个刷新任务。Wi-Fi 工作时功耗和供电需求高于 USB 单独待机；供电不稳可能重启。

默认密码供本地测试使用，知道热点密码的人可以操作屏幕。可在接收工程运行 `idf.py menuconfig` → **Ink Studio Wi-Fi** 修改热点名称和密码（8～63 个 ASCII 字符），然后重新编译烧录。不会把家庭 Wi-Fi 凭据写入工程。当前没有自动联网、浏览器图片编辑页面或无线升级；浏览器访问 `http://192.168.4.1/` 仅返回接收器说明。

若搜不到热点，确认烧入的是本次 1.2 接收固件并按 RESET；若连上后无法握手，检查电脑仍连接该热点、IP 地址、VPN/代理或防火墙。上位机 HTTP 客户端直接连接设备，不使用系统 HTTP 代理。固件网络初始化失败时会记录日志，USB 接收仍保留。

## 保存、重绘与导出

- 不勾“同时保存到设备”：图像只用于本次刷新，不写 Flash。屏幕仍可在断电后保留画面。
- 勾选后：成功刷新后把一张图片和 CRC 保存到 NVS，覆盖上一次保存的图片；相同 CRC 会跳过重复写入。
- **重绘已存图片**：让设备重新显示保存的那张图片，不需要重新传输；当前电脑预览不会因此替换。
- 重启设备不会自动重绘，避免每次插 USB 都进行一次全刷。保存的图像在重新上电后仍可手动重绘。
- **导出 PNG**：黑白红预览，按当前横竖屏方向保存。
- **导出 C 数组**：原生 104×212 的 `epd_image_black` / `epd_image_red`，可供原单图工程使用。
- **导出 BIN**：5512 字节，先黑层 2756 字节，再红层 2756 字节，不含文件头；每行高位在前，1 表示对应颜料，0 表示无该颜料，黑红不得重叠。

## 不接硬件也能试用

端口列表选择 **模拟设备 · 不连接硬件**，点击连接，再试发送、保存、重绘。
模拟流程约 2.3 秒完成，只验证软件流程，不会访问真实 COM 口，也不表示屏幕已经刷新。
模拟保存仅在当前连接期间有效；真实设备使用 NVS 保存，断电可保留。

## 刷新方式与当前限制

- 只支持这块屏当前已验证的全刷流程，未加入局刷。
- 原生 104×212；横屏编辑 212×104 会自动转换为屏幕原生数据顺序。
- 沿用新 PCB 已验证的引脚和初始化顺序：BUSY=GPIO3、RST=GPIO1、DC=GPIO5、SCLK=GPIO4、MOSI=GPIO6、CS=GPIO7。
- 温度参数暂固定为 25℃，全刷典型约 22 秒，实际时长取决于屏幕和环境；当前版本按室温使用。
- 同时只处理一次刷新，完成前禁用再次发送。进度表示处理阶段，不是精确计时百分比。
- 不自动重复刷新；不自动重试异常刷新。每个 BUSY 等待最多 120 秒，异常后停止后续显示操作。
- 如果刷新在 1 秒内报告结束，会作为异常处理。完成回复只代表驱动流程结束，仍需目视检查屏幕，SPI 本身无图像回读确认。
- 本版保持 USB 和 Wi-Fi 热点在线，未启用 ESP32 深度休眠；全刷结束会发送关闭升压命令并拉低屏幕 RST/DC。
- 串口断开不会取消设备已开始的刷新，刷新期间应继续保持供电。
- Wi-Fi 当前仅支持 C3 自建热点，不连接家庭路由器；未加入蓝牙、图库轮播或电池管理。

## 常见问题

**端口无法打开 / 拒绝访问**：关闭其他串口监视器，确认 USB 数据线和端口；同一时间只让一个程序占用 COM9。

**握手超时**：旧单图固件不支持本协议；先安装接收固件，按板上 RESET 后重新连接。日志中的乱码或启动文字不等于握手成功。

**USB 写入超时**：端口已经打开，但设备没有正常接收。旧显示程序不读取上位机命令时也可能出现这种情况，并不能仅凭此错误判定线坏了。先安装配套接收固件 1.2；已安装则按 RESET 或重新插拔 C3 USB 后再连接。连接失败和握手超时都会释放端口，方便安装固件。

**已连接但无法保存**：接收固件 1.2 会返回存储初始化错误；上位机取消并禁用保存，仍可传图显示。程序不会自动擦除原 NVS 数据。

**BUSY 等待超时**：看日志是卡在升压前、升压还是刷新。先断电，再检查排线、供电和焊接；程序不会强行跳过 BUSY。

**显示“流程完成”但屏幕没变**：确认选的是真实 COM 口，检查供电和排线；软件校验的是传到 C3 的数据，不是屏幕最终成像。

**保存失败**：屏幕可能已经刷新，但图片没有成功写入 NVS；界面会明确显示错误，不会把它当作保存成功。

## 开发与重新编译

源码文件说明：

| 文件 | 用途 |
| --- | --- |
| `app.py` | Qt 窗口、图片操作、设备状态、烧录入口 |
| `image_core.py` | 缩放裁切、黑白红转换、数据打包与导出 |
| `device.py` | 串口工作线程与模拟设备 |
| `wifi_device.py` | HTTP 工作线程、上传及进度轮询 |
| `firmware/main/wifi_transport.c` | C3 热点、HTTP 接口及会话事件日志 |
| `protocol.py` | 分包接收、请求与回复编码 |
| `firmware/main/receiver.c` | USB/Wi-Fi 命令、CRC、刷新任务、NVS 保存 |
| `firmware/main/epd_driver.c` | 沿用原工程的屏幕引脚与刷新时序 |
| `firmware/bin` | 已编译固件与 SHA256 清单 |
| `test_core.py`、`test_gui.py`、`test_device.py`、`test_wifi.py` | 图像、协议、Qt 完整流程及串口故障恢复测试 |

源码启动和测试（在 `image_tool` 目录）：

```powershell
powershell -ExecutionPolicy Bypass -File .\setup.ps1
.\.venv\Scripts\python.exe .\app.py
.\.venv\Scripts\python.exe -m unittest -v test_core test_gui test_device test_wifi
```

重新编译接收固件（在 ESP-IDF 5.4.x 的 PowerShell 终端中运行；原电脑也可自动加载环境，其他电脑可用 `-IdfProfile` 指定环境脚本）：

```powershell
powershell -ExecutionPolicy Bypass -File .\firmware\build_firmware.ps1
```

命令行安装接收固件，安装前关闭其他串口程序：

```powershell
powershell -ExecutionPolicy Bypass -File .\firmware\flash_firmware.ps1 -Port COM9
```

重新打包上位机（开发环境需另装 PyInstaller，交付版无需安装）：

```powershell
.\.venv\Scripts\python.exe -m pip install PyInstaller==6.22.3
powershell -ExecutionPolicy Bypass -File .\package.ps1
```

如需恢复原单图固件：关闭上位机，加载已有 IDF 环境，回到上一级 `epd_hello_idf` 工程运行 `idf.py -p COM9 flash`；不需要删除此工具。
